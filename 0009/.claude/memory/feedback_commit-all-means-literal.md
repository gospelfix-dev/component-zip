2026-09-03, "현재까지 작업한 모든 변경 파일 모두 커밋/푸쉬해줘" 요청에 처음엔 판단을 갈라서
커밋했다 — 1차로 `git status`의 "M"(이미 추적 중) 파일 + 명백히 사이트에서 참조되는 신규 에셋
(폰트, `fonts.css`/`init.css`, 참조되는 png)만 골라 커밋하고, `_debug_loc.html`
(참조 안 되는 디버그 사본), `.claude/plans/`·`.claude/agent-memory/`(Claude Code 툴 내부
스크래치), 미참조 png 샘플들은 스스로 판단해서 빼고 사용자에게 "이런 이유로 뺐다"고
보고했다. 그런데 사용자가 바로 "모든 변경 파일 다 커밋 해줘!"라고 **다시** 요청했고, 이번엔
남은 전부(디버그 파일·플랜·서브에이전트 메모리·미사용 이미지 포함)를 커밋했다.

**Why**: 사용자는 "모든 변경 파일"을 문자 그대로의 의미로 썼다 — "프로덕션에 의미 있는 파일만"
같은 암묵적 스코프 축소를 기대하지 않았다. 첫 판단(큐레이션)이 틀렸다기보다, 사용자가 재확인
요청을 한 시점에서 이미 답이 나온 것 — 애매한 항목을 스스로 판단해 제외하지 말고 그대로
포함했어야 다시 물을 필요가 없었다.

**How to apply**: 이 프로젝트에서 "모든/전부 변경 파일 커밋해줘" 같은 포괄적 커밋 요청을 받으면,
비밀값(시크릿)이 들어있는지만 확인하고 나머지는 큐레이션 없이 전부 스테이지한다. 정말 애매한
파일(예: 대상 폴더 밖 파일, 명백히 실수로 만들어진 산출물)이 있으면 커밋 전에 목록만 짧게
언급하고 진행하되, 사용자가 다시 "전부"라고 반복하면 그 즉시 이견 없이 포함한다.
[[gopumgyeok-landing-project]]의 저장소 범위(`0007`은 독립 폴더) 확인과 함께 적용할 것.

2026-09-09에 재확인: 실제 git 저장소 루트는 `component-zip`(0007과 0007-B의 공통 부모)이라,
"모두 커밋해줘"를 문자 그대로 적용하면 **다른 세션/에이전트가 만든 형제 폴더 `0007`의 변경
사항까지 같은 커밋에 함께 올라간다**(0007-B 작업 중에도 `git status`에 `0007/...` 변경이
같이 잡힘). "0007-B는 0007에 의존하지 않는 독립 폴더"라는 CLAUDE.md 원칙은 **코드 상의
의존성**에 대한 것이지 **git 커밋 범위**에 대한 것이 아니다 — "모두"라는 요청을 받으면
현재 작업 중인 폴더로 스코프를 좁히지 말고 저장소 전체의 변경 파일을 대상으로 `git add -A`
한다(비밀값 확인은 여전히 전체 대상으로 수행).

**2026-10-19 예외 확인, 0009**: "다른것도 다 커밋/푸쉬해줘"(0009 작업을 이미 한 번
커밋/푸쉬한 뒤의 **반복** 요청 — 위 사례 기준으로는 이견 없이 포함해야 할 상황)를 받고
`git status`를 저장소 루트(`component-zip`)에서 확인했더니 `.serena/`(Serena MCP 서버가
생성한 언어 서버 설정/캐시 디렉터리, 자체 `.gitignore`로 `cache`/`project.local.yml`을
이미 스스로 제외하고 있었음)만 미추적 상태였다. "전부 포함" 원칙을 그대로 적용하지 않고
AskUserQuestion으로 먼저 확인했고, 사용자는 "커밋하지 않음(권장) — `.gitignore`에 추가"를
선택했다.

**Why**: 위 디버그 파일·미참조 이미지·형제 폴더 변경 사례와 `.serena/`의 결정적 차이는
"프로젝트가 만들어낸 산출물인가, 로컬 도구가 머신에 남긴 실행 상태인가"다. 디버그 HTML이나
플랜 파일은 이 저장소 작업의 부산물(다른 머신에 clone해도 의미가 있음)이지만, `.serena/`는
`node_modules`/`.vscode`처럼 **이 머신·이 MCP 서버 설치에 종속된 상태**라 다른 사람이
clone하면 무의미하거나(캐시) 충돌 소지가 있다(`project.local.yml`). 디렉터리 이름이
연결된 MCP 툴 이름과 일치하고, 그 안에 자체 `.gitignore`가 이미 존재한다는 두 단서가
"프로젝트 산출물이 아니라 로컬 툴 상태"라는 신호다.

**How to apply**: "모두/전부 커밋해줘" 요청이라도, 미추적 디렉터리가 (a) 설치된 MCP
서버/로컬 도구 이름과 일치하고 (b) 그 안에 자체 `.gitignore`가 있다면 — 반복 요청이어도
곧장 포함하지 말고 AskUserQuestion으로 한 번 확인한다. 디버그 스크래치 파일·미참조
이미지·형제 폴더 변경처럼 "이 저장소 작업의 산출물"인 애매한 항목은 여전히 기존 원칙대로
확인 없이 포함한다 — 구분 기준은 "애매함의 정도"가 아니라 "프로젝트 산출물 vs 로컬 툴
상태"라는 범주 차이다. 커밋하지 않기로 하면 루트 `.gitignore`에 항목을 추가해 다음부터
`git status`에 계속 잡히지 않게 정리한다.
