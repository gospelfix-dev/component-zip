2026-10-14, 사용자가 efully.co.kr 레퍼런스를 보여주며 "메뉴 섹션 다음에 끊임없이 흐르는
마퀴(로고+문구) 티커를 추가해달라"고 요청했다. 이 프로젝트(0008)는 `.claude/rules/02-css.md`에
"무한 반복 애니메이션(팝/샤인/블링크/스냅류)을 만들지 않는다"는 절대 규칙이 있고, 배포 전
회귀 스윕이 `grep infinite assets/css/*.css` 결과를 0건으로 강제하는 구조였다.

요청을 그대로 구현하면 규칙을 정면으로 어기고, 규칙을 들어 거절하면 사용자의 명시적 요청을
무시하는 셈이었다. 둘 다 하지 않고, AskUserQuestion으로 "①무한 마퀴로 예외 허용(레퍼런스와
동일) ②스크롤 연동 방식으로 대체 ③1회성 슬라이드 리빌로 대체" 3가지 선택지를 제시했다 —
사용자는 "무한 마퀴로 예외 허용"을 선택했다.

**Why**: 확정 규칙(특히 회귀 스윕에 하드코딩된 수치 기준처럼 "지켜지고 있는지 기계적으로
검증 가능한" 규칙)은 이전 세션/사용자가 의도를 갖고 못박은 결정이다. 요청이 그 규칙과
충돌한다는 사실 자체를 사용자가 인지하고 있는지 알 수 없으므로, 임의 해석으로 규칙을
깨거나 요청을 축소 구현하지 않고 선택권을 사용자에게 돌려준다.

**How to apply**: 이 프로젝트에서 새 요청이 `.claude/rules/*.md`의 "절대 규칙" 문구(무한
반복 애니메이션 금지, 색상 토큰만 사용, font-size 12~120px, 단일 브레이크포인트 등)와
충돌하면: (1) 구현 전에 먼저 충돌 지점을 짧게 설명하고, (2) 규칙을 지키는 대안 1~2개와
"명시적 예외 허용" 옵션을 함께 제시해 AskUserQuestion으로 묻는다. 사용자가 예외를
선택하면 그 즉시 관련 규칙 문서(CLAUDE.md, 해당 `.claude/rules/*.md`, `docs/design.md`)에
"이것은 의도된 유일한 예외"라고 명시해, 다음 세션이 회귀로 오인해 되돌리지 않게 한다
(실제로 이번에 `.claude/rules/02-css.md`·`CLAUDE.md`·`docs/design.md` 세 곳 모두에
마퀴 예외를 기록해뒀다).

**2026-10-16, 0009(연두)에서 재확인**: `border`/`box-shadow` 금지 규칙(`docs/06-elevation.md`)과
충돌하는 요청이 같은 대화에서 두 번 나왔다 — ①"헤더 밑에 흰 선" 요청 때는 AskUserQuestion으로
물어 사용자가 "배경색 차이로만 구분(규칙 준수)"을 선택했고, ②헤더를 `position: fixed`
플로팅으로 바꾼 뒤 "보더"라는 단어로 다시 요청했을 때는 같은 방식으로 물었더니 이번엔
"실제 border-bottom 추가(규칙 예외)"를 선택했다. 같은 종류의 충돌이라도 요청마다 사용자의
답이 달라질 수 있으므로, 한 번 규칙 준수를 택했다고 다음에도 같은 결론이라고 넘겨짚지 말고
충돌이 생길 때마다 다시 묻는다. 이 절차는 0008뿐 아니라 이 모노레포의 다른 폴더(0009 등)에도
동일하게 적용된다 — 폴더 전용이 아니라 `component-zip` 전반의 작업 방식으로 취급한다.

**2026-10-16, 0009 후속 세션에서 대량 재확인**: 같은 대화 안에서 유형이 다른 절대 규칙
충돌이 6건 더 발생했다 — 히어로 H1/Body 폰트 크기가 `docs/03-typography.md` 표를 초과,
`.site-header`에 `radius-base`를 버튼/카드/이미지 외 용도로 재사용, `backdrop-filter:
blur()`가 "평평한 UI(그림자·테두리·그라데이션 금지)" 원칙과 충돌, motion.dev를 CDN으로
불러오는 것이 "외부 CDN 금지" 절대 규칙과 충돌, 폰트 웨이트를 400/500/700에서 800/900으로
확장, `README.md`에 박힌 "워드마크는 모두 소문자" 브랜드 결정을 대문자로 변경. 매번
AskUserQuestion으로 먼저 물었고, **6건 전부 사용자가 "예외로 진행"을 선택**했다(규칙 준수
대안을 고른 경우는 0건). 그렇다고 "이 사용자는 항상 예외를 택한다"고 넘겨짚어 다음부터
묻지 않고 바로 예외 처리하면 안 된다 — 바로 위 0008 사례처럼 같은 종류 충돌도 상황마다
답이 갈릴 수 있고, 무엇보다 사용자가 매번 "지금 이 요청이 기존 규칙과 충돌한다"는 사실을
인지한 상태에서 선택하게 하는 것 자체가 핵심이므로, 이 "거의 항상 예외 선택" 경향은
판단 참고용 사전 정보일 뿐 질문 생략의 근거가 아니다. 예외를 승인받을 때마다 관련
`docs/*.md`·`.claude/rules/*.md`·`CLAUDE.md`·`README.md`에 "n월n일 사용자 확정" 형태로
즉시 기록해 다음 세션이 회귀로 오인하지 않게 하는 절차도 6건 전부에서 그대로 유지했다.
