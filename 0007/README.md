## 5. 5섹션 구조 (최종 확정)

내비게이션 5개 항목 = 섹션 5개. 클릭 시 `scrollIntoView`로 스무스 스크롤.

1. **경쟁력** (`#competitiveness`) — 3대 핵심경쟁력 카드(Premium Quality / 고품격 샐러드 / 물결형 인테리어) + 트러스트 스트립(HACCP, 7호점, 25종+, ECO)
2. **메뉴** (`#menu`) — 고기 9종 그리드 + 셀프바 25종 원형 그리드
3. **수익분석** (`#profit`) — **영수증 롤 스타일**. 왕십리/천호/시흥은계 3개 매장의 실제 월매출(카탈로그 기준: 47,000,000 / 67,000,000 / 39,000,000원)과 순수익률(36.1% / 40.2% / 33.3%)을 프린터에서 종이가 뽑혀 나오는 스크롤 애니메이션으로 표시
4. **창업비용** (`#cost`) — 항목표(가맹비/교육비/보증금/인테리어/설비/초도물품). **⚠️ 실제 금액 데이터가 카탈로그에 없어서 전부 "상담 시 안내"로 표기되어 있음.** 실제 비용 데이터를 받으면 채워야 함.
5. **매장위치** (`#location`) — 매장 3곳 카드 + 문의폼(이름/연락처/문의유형/문의내용) — 지금은 목업이라 제출해도 실제 DB 연동 없음, 버튼 텍스트만 바뀜

히어로 섹션은 내비게이션에 포함되지 않는 인트로 섹션.

## 7. 영수증(리시트) 카드 — 반복 수정된 디테일 (03 수익분석)

여러 차례 피드백을 거쳐 확정된 구조:

```
.receipt-col (전체 wrapper, --d 커스텀 프로퍼티로 stagger delay 지정)
 └─ .printer-bar (메탈릭 알약형 외곽)
     ├─ .printer-endcap.left (흰색 사각 엔드캡)
     ├─ .printer-slot (검은 리세스 슬롯)
     └─ .printer-endcap.right
 └─ .receipt-mask (overflow:hidden, max-height 0→760px 애니메이션 컨테이너)
     └─ .receipt-body (opacity 0→1, filter:drop-shadow — box-shadow 아님!)
         ├─ .receipt-paper (크림색 종이, 라벨/매장명/매출/순수익률/날짜/바코드)
         └─ .receipt-scallop (하단 스캘럽 절취선 — mask-image 반원 패턴)
```

**중요한 기술적 교훈 (재작업 시 참고)**:
- 종이 그림자는 `box-shadow`가 아니라 **`filter:drop-shadow()`를 wrapper에** 걸어야 함. `box-shadow`를 종이 자체에 걸면 스캘럽 절취선의 투명한 틈 사이로 그림자가 새어나와 회색으로 보이는 버그 발생했었음.
- 스캘럽(둥근 물결) 절취선은 `clip-path` 삼각형이 아니라 `mask-image: radial-gradient(circle ...)` 반복 패턴으로 구현. 뾰족하게 만들려면 원 지름을 반복 간격(tile width)보다 크게 잡아서 인접 원끼리 겹치게 해야 함 (현재 반지름 10px / 간격 14px).
- 스크롤 진입 애니메이션은 `IntersectionObserver`로 `.receipt-col`에 `in-view` 클래스를 추가하는 방식. 한 번 트리거되면 `unobserve` 처리(재반복 안 함).
- 매출 숫자 뒤 "원" 단위는 **삭제됨** (사용자 요청).
- 폰트 크기는 카드 폭 대비 최대한 크게: 매장명 `clamp(30px,8.5vw,42px)`, 매출 숫자 `clamp(32px,9vw,44px)`.

## 8. JavaScript 구조 (script.js, ES6)

주요 함수:
- `profitData` — 매장별 수익 데이터 배열 (하드코딩, 카탈로그 실측치)
- `formatWon(n)` — 숫자 3자리 콤마 포맷
- `renderProfitCards(data, containerId)` — 영수증 카드 DOM 생성 (템플릿 리터럴)
- `initReceiptReveal()` — IntersectionObserver로 스크롤 진입 애니메이션 트리거
- `initSmoothScroll()` — nav의 `data-target` 클릭 시 `scrollIntoView`
- `initMobileNav()` — 900px 이하 햄버거 메뉴 토글
- `initScrollSpy()` — 스크롤 위치에 따라 현재 섹션 nav 하이라이트 + 헤더 배경 전환
- `initInquiryForm()` — 문의폼 제출 시 버튼 텍스트만 변경 (실제 전송 없음, 목업)

전부 `DOMContentLoaded` 시점에 순서대로 초기화됨.

## 9. 알려진 제약사항 / 확인 필요 사항

1. **브라우저 렌더링 도구 없음**: 이 환경(claude.ai 컨테이너)에는 Chromium/Playwright 바이너리를 설치할 네트워크 권한이 없어서, 지금까지의 모든 CSS 수정은 **실제 스크린샷으로 검증하지 못한 상태**입니다. CLI 환경(로컬)에서는 반드시 브라우저로 직접 열어서 픽셀 단위 검증 필요.
2. **창업비용 섹션에 실제 금액 없음**: 카탈로그에 가맹비/교육비 등 구체적 금액이 없어서 전부 "상담 시 안내"로만 표기됨. 실제 수치를 받으면 `index.html`의 `.cost-table` 부분과 `script.js` 없이 정적으로 되어 있으니 바로 수정 가능.
3. **문의폼은 완전 목업**: Supabase 연동 안 됨. 실제 프로덕션에서는 이전 대화(기획서 v2)에서 논의된 `@supabase/ssr` + RLS 정책 기반으로 구현 예정.
4. **이미지가 전부 카탈로그 PDF 크롭본**: 저해상도 원본이라 실제 프로덕션에서는 클라이언트로부터 고해상도 원본 사진을 받아 교체하는 게 좋음.
5. **지그재그 → 스캘럽 절취선 변경 이력**: 처음엔 `clip-path` 삼각형 지그재그로 만들었다가, 참고 이미지가 둥근 스캘럽이라는 걸 확인하고 `mask-image` 방식으로 전면 교체함. 혹시 다른 섹션에도 절취선을 쓸 일이 있으면 스캘럽(`mask-image`) 방식을 기본으로 쓸 것.
