2026-09-03, "현재까지 작업한 모든 변경 파일 모두 커밋/푸쉬해줘" 요청에 처음엔 판단을 갈라서
커밋했다 — 1차로 `git status`의 "M"(이미 추적 중) 파일 + 명백히 사이트에서 참조되는 신규 에셋
(폰트, `fonts.css`/`init.css`, 참조되는 png)만 골라 커밋하고, `_debug_loc.html`
(참조 안 되는 디버그 사본), `.claude/plans/`·`.claude/agent-memory/`(Claude Code 툴 내부
스크래치), 미참조 png 샘플들은 스스로 판단해서 빼고 사용자에게 "이런 이유로 뺐다"고
보고했다. 그런데 사용자가 바로 "모든 변경 파일 다 커밋 해줘!"라고 **다시** 요청했고, 이번엔
남은 전부(디버그 파일·플랜·서브에이전트 메모리·미사용 이미지 포함)를 커밋했다.

**Why**: 사용자는 "모든 변경 파일"을 문자 그대로의 의미로 썼다 — "프로덕션에 의미 있는 파일만"
같은 암묵적 스코프 축소를 기대하지 않았다. 첫 판단(큐레이션)이 틀렸다기보다, 사용자가 재확인
요청을 한 시점에서 이미 답이 나온 것 — 애매한 항목을 스스로 판단해 제외하지 말고 그대로
포함했어야 다시 물을 필요가 없었다.

**How to apply**: 이 프로젝트에서 "모든/전부 변경 파일 커밋해줘" 같은 포괄적 커밋 요청을 받으면,
비밀값(시크릿)이 들어있는지만 확인하고 나머지는 큐레이션 없이 전부 스테이지한다. 정말 애매한
파일(예: 대상 폴더 밖 파일, 명백히 실수로 만들어진 산출물)이 있으면 커밋 전에 목록만 짧게
언급하고 진행하되, 사용자가 다시 "전부"라고 반복하면 그 즉시 이견 없이 포함한다.
[[gopumgyeok-landing-project]]의 저장소 범위(`0007`은 독립 폴더) 확인과 함께 적용할 것.
