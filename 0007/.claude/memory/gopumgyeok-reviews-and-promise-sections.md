2026-09-08 세션에서 `index.html`에 섹션 두 개가 새로 추가됐다. 번호가 있는 기존 6섹션(01~05 +

`data/content.json`의 섹션 키, JS 셀렉터 어디에도 영향을 주지 않기 위한 선택이다. 새 중간 섹션을

## 03.5 창업 안내 배너 (`.promise`, `#promise`) — 03 수익분석과 04 창업비용 사이

`assets/imgs/con_bg.png`를 배경으로 쓰는 패럴랙스 배너. [[gopumgyeok-hero-parallax]]에 문서화된
`.hero-bg`의 `background-attachment:fixed` 기법을 그대로 재사용했다(sticky는 아니고 배경 고정만).
모바일/터치 기기 폴백(`@media (max-width:1024px), (hover:none)`)과
`prefers-reduced-motion`(`.promise-bg{background-attachment:scroll}`) 예외도 `.hero-bg`와 동일하게
챙겨야 한다 — 새 패럴랙스 배경을 추가할 때마다 이 세 곳(기본/터치폴백/reduced-motion)을 세트로
묶어야 하는 게 이 프로젝트의 반복 패턴이다.

카피는 초안("숨김없이 보여드리는 고품격대패의 진심" — 신뢰/투명성 톤)에서 사용자 요청으로
"지금 시작하는 창업, 고품격대패가 함께합니다"(창업 안내 톤)로 교체됐다 — 04 창업비용 섹션 바로
앞이라 "창업"을 주제로 한 카피가 더 잘 맞는다는 판단. `.promise-overlay`의 다크 오버레이는
`linear-gradient(180deg, rgba(10,8,6,X) 0%, ... 45%, ... 100%)` 구조인데, 최초 값(`.78/.55/.82`)이
너무 어둡다는 피드백으로 두 차례에 걸쳐 `.54/.45/.58`까지 낮췄다 — 이 배너는 사용자가 "은은하게"
보이길 원한다는 뜻이라, 나중에 또 밝기 조정 요청이 오면 이 방향(더 연하게)으로 계속 갈 가능성이 높다.

## 02.5 소비자 찐후기 (`.reviews`, `#reviews`) — 02 메뉴와 03 수익분석 사이

매장 3곳(시흥 은계점=`review1.png`, 왕십리 본점=`review2.png`, 천호 직영점=`review3.png`, 매핑은
`data/content.json`의 `stores[]` 순서와 무관하게 이 세 리뷰 스크린샷 자체의 매장명으로 고정)마다
빨간 필 배지(`.review-badge`, "매장명 리뷰 N+")와 아이폰 목업(`.review-phone`)을 나열한다. 헤더
nav에도 "소비자 찐후기"(`#reviews`) 링크를 메뉴↔수익분석 사이에 추가했다 — `initSmoothScroll`/
`initScrollSpy`가 `[data-target]`/`section[id]`를 범용으로 스캔하므로 JS 수정은 필요 없었다.

### 아이폰 목업 합성 기법 — 이 세션에서 가장 반복적으로 손댄 부분

`.review-phone__frame`(`assets/imgs/iphone.png`, 화면 부분이 투명한 PNG)을 위 레이어로, 실제 리뷰
스크린샷(`.review-phone__screen`)을 아래 레이어로 겹쳐서 폰 화면에 스크린샷이 끼워진 것처럼
합성한다. **`iphone.png`는 이 세션 동안 사용자가 세 번 교체했고**(2000×2000 정사각 → 1622×3238
크롭 → 1538×3120 "고품격대패" 브랜드 헤더 내장 버전), **교체될 때마다 `.review-phone`의
`aspect-ratio`와 `.review-phone__screen`의 `left/top/width/height` 퍼센트를 처음부터 다시 구해야
했다** — 이 값들은 이전 이미지 크기에서 계산한 것이라 새 이미지에 그대로 쓰면 스크린샷이 베젤
밖으로 삐져나오거나 안쪽에 빈 여백이 남는다.

**재계산 절차(다음에 또 iphone.png가 바뀌면 이 순서로):**
1. Python(PIL)으로 새 이미지의 알파 채널을 읽어 투명한 "화면 구멍"의 실제 픽셀 좌표를 찾는다
   (`alpha>10`을 불투명으로 보고, 안정적인 몸통 구간의 y값 여러 곳에서 좌우 경계를 스캔 — 코너가
   둥글게 말리는 최상단/최하단 근처는 피할 것).
2. 좌표를 전체 캔버스 대비 퍼센트로 환산한다.
3. **실제 브라우저로 검증한다** — PIL로 합성 테스트 이미지를 만들어보는 것도 방향을 잡는 데
   도움이 되지만, [[gopumgyeok-review-image-scaling-bug]]에 적은 것처럼 **브라우저의 실시간
   축소 렌더링은 PIL 결과와 다르게 나올 수 있다.** 반드시 로컬 서버 + 헤드리스 스크린샷(또는
   screenshot-verifier 에이전트)으로 실제 렌더링을 확인해야 한다.
4. 최신 확정값(1538×3120 브랜드 헤더 버전 기준): `.review-phone{aspect-ratio:1538/3120}`,
   `.review-phone__screen{left:4.2%; top:8.5%; width:92%; height:90%; border-radius:0 0 10px 10px}`
   — 상단 모서리는 각지게, 하단만 둥글게(사용자가 상단 좌/우 radius만 제거해달라고 명시).

### 여백/크기 관련 피드백 — 이미지 버전에 따라 정반대로 뒤집혔다

같은 "스크린샷이 폰 화면에 얼마나 꽉 차야 하는가"에 대한 피드백이 iphone.png 버전이 바뀔 때마다
**정반대로** 나왔다:
- 옛 프레임(카메라 노치만 있던 버전)에서는 스크린샷을 화면 구멍에 꽉 채웠더니 "너무 꽉 찬
  느낌"이라는 피드백 → 사방으로 한 단계 안쪽으로 줄여 여백을 줬다.
- 새 프레임(브랜드 헤더 내장 버전)으로 바뀐 뒤에는 반대로 "블로그 이미지가 핸드폰 칸에 꽉차게"
  요청 → 실측 화면 구멍에 가깝게 다시 채웠다.

**Why:** 여백의 적정선은 프레임 디자인 자체에 달려 있다(브랜드 헤더가 있으면 그 자체가 이미
시각적 여백 역할을 해서 스크린샷은 꽉 차는 게 낫고, 노치만 있으면 스크린샷이 베젤에 바로
붙어 답답해 보인다). **How to apply:** iphone.png가 또 바뀌면 "꽉 차게/여백 두고" 둘 다 재확인
받을 것 — 이전 프레임에서의 정답이 새 프레임에서는 오답일 수 있다.

배지(`.review-badge`)와 폰 사이 간격도 한 차례 뒤집혔다: 겹치게(`margin-bottom:-26px`) 했더니
배지가 카메라 노치를 가려서 다시 띄웠다(`margin-bottom:20px`, 최종 확정값). 모바일 2열 그리드
(~200px 폭)에서 "왕십리 본점 리뷰 675+"처럼 긴 배지가 `white-space:nowrap`이면 화면 밖으로
밀려나는 것도 발견해 `@media (max-width:1024px)` 안에서만 `font-size:18px`(전역 최소 허용치)
+ `white-space:normal`로 줄바꿈을 허용했다.
