**상태: 미해결, 조사 중단됨.** 2026-09-08, [[gopumgyeok-reviews-and-promise-sections]]의
"소비자 찐후기" 섹션에서 `assets/imgs/review1.png`(시흥 은계점 카드)만 텍스트와 아이콘(⭐️✕)이
심하게 뭉개져 보인다는 걸 사용자가 스크린샷으로 신고했다. 조사 도중 사용자가 "야! 지금 작업
꺼줘"로 즉시 중단시켜서 **원인도 못 찾고 수정도 안 한 상태로 남아 있다.** 다음 세션에서 이
증상이 다시 보고되면 아래 조사 내역부터 이어서 확인할 것.

## 증상
`review1.png`(현재 파일 600×1308, PNG, RGBA, ICC 프로파일 포함)를 `.review-phone__screen`
(`object-fit:cover`로 표시 폭 ~150~280px까지 축소)에 넣으면 한글 텍스트 획이 뭉개지고 별/X
아이콘도 찌그러진다. 헤드리스 Chrome과 사용자의 실제 브라우저 양쪽에서 재현됐다 — 즉 headless
전용 렌더링 버그가 아니라 실제로 나타나는 문제다. **`review2.png`/`review3.png`는 거의 동일한
크기·비율·용도의 이미지인데도 이 증상이 없다** — 이미지 콘텐츠 특이적인 것으로 보인다.

## 조사한 내용 (원인 확정 못 함)
- 소스 파일 자체(600×1308, 축소 없이 그대로 열어봄)는 완전히 깨끗하다 — 문제는 오직 브라우저가
  **실시간으로 축소 렌더링**할 때만 나타난다.
- PIL(Python)로 오프라인 리샘플링(`Image.LANCZOS`)한 결과는 어떤 축소 비율에서도 항상 깨끗했다
  — 즉 이미지 데이터 자체는 정상이고, **브라우저의 실시간 다운스케일 알고리즘**이 문제일
  가능성이 높다.
- 축소 비율과의 상관관계를 격리 테스트(`.review-phone__screen`과 동일한 CSS만 떼어낸 최소
  HTML)로 확인한 결과:
  - 소스 600px → 표시 552px(~8% 축소): 깨끗함
  - 소스 600px → 표시 400px(~33% 축소): 뭉개짐
  - 소스 600px → 표시 180~300px(~50~70% 축소): 뭉개짐
  - **소스를 300px로 미리 줄여서 표시 262px(~13% 축소)로 렌더링하면 깨끗함** — 즉 "축소 비율을
    작게 유지하면" 증상이 사라진다.
- 하지만 이 섹션은 반응형이라 `.review-phone`의 실제 렌더 폭이 뷰포트에 따라 ~135px(모바일 2열
  그리드)부터 ~276px(데스크톱)까지 넓게 변한다. 소스를 300px로 고정하면 데스크톱에서는 축소
  비율이 작아 괜찮겠지만 **모바일 좁은 폭에서는 다시 큰 비율로 축소되어 재발할 가능성이 높다**
  (직접 검증은 못 함 — 여기서 중단됨).
- ICC 컬러 프로파일 유무는 세 파일 모두 있어서 차이를 설명 못 한다. PNG 인터레이스 여부도 세
  파일 다 동일(비-인터레이스)이라 차이를 설명 못 한다.

## 다음 세션에서 시도해볼 것 (미검증 가설)
1. `review1.png`만 다른 두 파일과 정말 "같은 종류"인지 픽셀 단위로 더 깊이 비교(예: 특정
   주파수 대역의 디테일이 유독 많은지, 텍스트 획 두께가 얇은지 등 — 반복무늬가 다운샘플링과
   간섭해 생기는 무아레 현상일 가능성).
2. `srcset`/여러 해상도 사본을 만들어 뷰포트별로 적절한 크기를 제공(반응형 이미지) — 정적
   사이트라 빌드 도구 없이 손으로 2~3개 사본을 만들어야 한다.
3. `image-rendering` CSS 속성(`auto`/`smooth` 등) 실험 — 표준값이 제한적이라 효과 없을 수 있음.
4. 이 문제가 **review1.png에만 국한된 콘텐츠 이슈**라면, 차라리 사용자에게 그 스크린샷을 약간
   다시 잘라내거나 재저장해서 받는 것도 방법.
