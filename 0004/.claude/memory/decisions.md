# 설계 결정 기록

세션 시작 시 `.claude/hooks/load-memory.sh` 가 이 파일을 컨텍스트로 주입한다.
코드만 봐서는 알 수 없는 **"왜"** 만 적는다. 코드 구조 설명은 쓰지 않는다.

---

## ES6 로 쓰면서 ES Modules 는 쓰지 않는 이유

요구사항은 "ES6 로 작성"이지 "모듈로 분리"가 아니었다.
`<script type="module">` 을 쓰면 `file://` 에서 모듈 로딩이 CORS 로 막혀 화면이 완전히 빈다.
이 저장소의 컴포넌트는 **파일을 더블클릭해서 확인하는 워크플로**를 전제로 하므로,
문법은 ES6 로 올리되 파일 분리는 IIFE + 전역 네임스페이스(`window.NameCard`, `window.Avatar`)로 했다.

빌드 도구를 도입하면 해결되지만, 무빌드 원칙이 더 우선한다.

## `FALLBACK` 중복을 감수한 이유

`js/app.js` 의 `FALLBACK` 은 `data/cards.json` 과 내용이 겹친다.
중복을 알면서도 유지하는 이유는 위와 같다 — `file://` 에서 `fetch` 도 CORS 로 막히기 때문이다.
`.claude/hooks/validate-cards.sh` 가 `id` 목록 동기화를 검사하고,
값까지 대조하는 건 `contact-link-check` 에이전트의 몫이다.

## 테마를 클래스가 아니라 "카드 스코프 토큰 재정의"로 만든 이유

시안의 5종 명함은 색만 다른 게 아니라 아이덴티티 블록의 **위치**가 다르다
(사진 위 / 회색 헤더 / 솔리드 배너 / 사진 아래). 처음엔 테마마다 템플릿을 따로 두려 했으나,
연락처·링크·소개 블록은 전부 같아서 템플릿이 4배로 불어나기만 했다.

그래서 **배치는 `THEMES` 맵의 두 축(`identity`, `contact`)으로**,
**색은 카드 스코프 CSS 변수 재정의로** 분리했다.
새 테마를 추가할 때 건드릴 곳이 JSON·CSS 토큰·`THEMES` 세 줄로 끝난다.

`--card-accent` 만 CSS 가 아니라 JS 가 인라인으로 주입하는데,
같은 `dark` 테마여도 이한결은 네이비, 이수환은 그린이기 때문이다.
색을 CSS 에 고정하면 테마가 무한히 늘어난다.

## 글래스 박스의 반투명을 `::before` 에 건 이유

`.identity--overlay` 자체에 `opacity` 를 주면 그 안의 이름·직책 텍스트까지 흐려져
사진 위에서 대비가 무너진다. `::before` 에 배경만 깔고 `z-index: -1` 로 내리면
텍스트는 완전 불투명하게 유지된다.

`backdrop-filter` 는 미지원 브라우저에서 무시되지만, `--glass-alpha` 가 0.84 라
블러 없이도 텍스트 대비가 유지된다. 그래서 별도 폴백 규칙을 두지 않았다.

## 인물 사진을 SVG 로도 그릴 수 있게 둔 이유

`imgs/` 에 아직 실사 에셋이 없다. `js/avatar.js` 가 `id` 를 시드로 인물 실루엣을 그려
사진 없이도 레이아웃을 검토할 수 있게 했다.

`photo` 에 경로를 넣는 순간 사진으로 바뀌므로, 사진을 받은 뒤에도 이 경로를 지우지 않는다.
새 명함을 기획 단계에서 미리 배치해 볼 때 다시 쓰인다.

## 아바타에 시드 난수를 쓰는 이유

`Math.random()` 을 쓰면 새로고침마다 얼굴·정장 색이 바뀌어
디자인 검토 중 "방금 전과 다르다"는 착시를 준다. `id` 해시를 시드로 고정했다.

`photoShape` 3종은 **같은 그림을 다른 `viewBox` 로 크롭**한 것이다.
따로 그리지 않았으므로, 인물 좌표를 바꾸면 세 크롭이 전부 영향을 받는다.

## Swiper 를 CDN 이 아니라 로컬 파일로 둔 이유

처음엔 갤러리를 CSS `scroll-snap` 만으로 만들었다. 동작은 했지만 드래그 관성·페이지네이션·
끝단 표시가 없어 명함을 넘긴다는 느낌이 약했다. 그래서 Swiper 로 바꿨다.

`0002` 가 이미 같은 버전(8.4.7)을 벤더링하고 있어 그 파일을 그대로 복사했다.
CDN 을 쓰지 않은 건 **`file://` 로 열었을 때도 슬라이더가 동작해야 하기 때문**이다.
외부 스크립트를 금지한 원칙과도 맞는다. 대신 저장소에 144KB 가 들어왔다 —
무빌드·오프라인 동작을 얻는 대가로 받아들인 용량이다.

"프레임워크 도입 금지" 규칙의 유일한 예외이며, 이 예외를 더 늘리지 않는다.

## `--card-w` 를 `:root` 로 올린 이유

원래 `.namecard` 안에 있었다. Swiper 로 바꾸면서 **폭을 정하는 주체가 `.swiper-slide` 로
옮겨졌는데**, 슬라이드는 카드의 부모라 `.namecard` 스코프 변수를 읽을 수 없었다.
둘 다 읽어야 하므로 `:root` 로 올렸고, 미디어쿼리도 `:root` 를 재정의하도록 바꿨다.

## 끝단 버튼의 `disabled` 는 우리가 걸지 않는다

Swiper 8 의 navigation 모듈은 nav 요소의 `tagName` 이 `BUTTON` 이면
`el.disabled = swiper.isEnd` 를 **직접 설정한다.** 클래스만 붙는 줄 알고 동기화 코드를
따로 짰다가, 실측해 보니 Swiper 가 먼저 걸고 있어 중복이었다. 그래서 걷어냈다.

**마크업을 `<a>` 로 바꾸면 이 동작이 사라진다.** 이전/다음은 `<button>` 으로 유지한다.

남은 진짜 문제는 포커스였다. Swiper 가 `disabled` 를 거는 시점이 `slideChange` 이벤트보다
빨라서 "끄기 전에 포커스를 옮긴다"가 불가능했다. 그래서 `focusout` 에서 —
갈 곳 없이(`relatedTarget === null`) 비활성화 때문에 빠져나갔을 때만 —
반대편 버튼으로 넘겨주는 방식으로 바꿨다. 키보드로 끝까지 넘겨도 포커스를 잃지 않는다.

## 페이지네이션 특정성 문제

`.gallery__pagination { width: auto }` 가 안 먹어 컨트롤이 좌우 끝으로 벌어졌다.
원인은 swiper.css 의 `.swiper-pagination-bullets.swiper-pagination-horizontal`(0-2-0)이
`width: 100%` 로 이긴 것. `!important` 대신 `.gallery__controls .gallery__pagination` 으로
같은 무게를 맞춰 해결했다.

Swiper 스타일을 덮어쓸 때 이 패턴이 또 나온다. 안 먹으면 추측하지 말고
`getComputedStyle` 로 실제 값을 찍어보는 편이 빠르다.

## 미해결 / 검토 대기

- `data/cards.json` 의 `links[].href` 가 전부 `#` 다. 실제 카카오톡 채널·가이드 URL 로 교체 필요.
- `imgs/` 가 비어 있다. 실사 사진을 넣으면 `card-design-qa` 로 크롭 위치를 다시 맞춰야 한다.
- `blue` 테마 김서정 카드의 `role` 이 빈 문자열이다. 직책은 `meta` 에 들어가 있어 의도된 것이지만,
  다른 테마와 데이터 모양이 달라 혼동 여지가 있다.
