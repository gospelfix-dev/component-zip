# 설계 결정 기록

세션 시작 시 `.claude/hooks/load-memory.sh` 가 이 파일을 컨텍스트로 주입한다.
코드만 봐서는 알 수 없는 **"왜"** 만 적는다. 코드 구조 설명은 쓰지 않는다.

---

## 제품컷을 `<img>` 와 SVG 두 갈래로 두는 이유

초기에는 사진 에셋이 없어 `js/popsicle.js` 가 SVG 로 아이스크림을 그렸다.
이후 `imgs/` 의 실사 PNG 로 교체했지만, **SVG 경로를 지우지 않았다.**

`image` 를 `null` 로 되돌리면 즉시 SVG 로 대체되므로,
새 맛을 기획 단계에서 미리 배치해 볼 때 사진 없이도 카드를 채울 수 있다.

## `FALLBACK` 중복을 감수한 이유

`js/app.js` 의 `FALLBACK` 은 `data/palettes.json` 과 내용이 겹친다.
중복을 알면서도 유지하는 이유는 **`file://` 로 열었을 때 `fetch` 가 CORS 로 막히기 때문**이다.
로컬 서버 없이 파일을 더블클릭해서 확인하는 워크플로를 지키기 위한 의도적 중복이다.

빌드 도구를 도입하면 해결되지만, 무빌드 원칙이 더 우선한다.

## 호버 확대 기준점이 `center top` 인 이유

참고 시안에서 호버된 카드는 아이스크림의 **베어문 단면**이 강조된다.
`transform-origin` 을 `center top` 으로 두면 확대 시 상단이 고정되어 단면이 항상 온전히 보이고,
잘리는 쪽은 정보량이 적은 나무 막대뿐이다.

`overflow: hidden` 을 카드가 아니라 `.palette-card__media` 에만 건 것도 같은 이유다.
카드에 걸면 확대된 이미지가 위쪽 텍스트를 침범한다.

## 토핑 배치에 시드 난수를 쓰는 이유

`Math.random()` 을 쓰면 새로고침마다 SVG 아이스크림의 토핑 위치가 바뀌어
디자인 검토 중 "방금 전과 다르다"는 착시를 준다. `id` 해시를 시드로 고정했다.

## 미해결 / 검토 대기

- 컴포넌트 이름이 `palette-card` 로 남아 있다. `FlavorCard` 로 확정되면
  HTML `<template>`, CSS 클래스, JS `querySelector` 를 동시에 바꿔야 한다.
- `imgs/` PNG 가 장당 1MB 내외다. 배포 전 `asset-optimizer` 에이전트로 점검 필요.
