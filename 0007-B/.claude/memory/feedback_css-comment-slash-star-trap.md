`assets/css/style.css`의 섹션 헤더 주석에 `(.meat-*/.selfbar-*)`처럼 클래스 prefix 두 개를
슬래시로 나열해 적었더니, 그 안의 `*/`가 CSS 파서에게는 **주석 종료 토큰**으로 읽혀 주석이
의도보다 훨씬 일찍 끝났다. 그 뒤에 남은 텍스트(`.selfbar-*) ... */`)가 깨진 CSS로 파싱되며
에러 복구 과정에서 바로 다음 규칙(`.meat-grid{ display:grid; ... }`)까지 통째로 삼켜버려,
`.meat-grid`가 `cssRules`에서 아예 사라졌다(`sheet.cssRules`를 순회해 확인). 화면에는 그냥
"grid가 적용 안 된 것처럼" 조용히 보여서, 클래스명/HTML 구조를 먼저 의심하며 디버깅 시간을
많이 썼다.

**Why**: CSS 주석은 `/* ... */`로 첫 번째 `*/`에서 무조건 끝난다 — 안에 다른 텍스트가
있어도 예외가 없다. "`.a-*`와 `.b-*` 계열"처럼 클래스 이름 뒤에 `*`를 붙이고 슬래시로
나열하는 표기 습관이 있으면, 우연히 `*/` 2글자 시퀀스가 만들어져 이 함정에 빠진다.

**How to apply**: CSS 파일의 한글 섹션 주석에서 클래스 prefix를 여러 개 나열할 때는
`.a-*, .b-* 계열`처럼 **쉼표+공백**으로 구분하고 `*` 바로 뒤에 `/`가 오지 않게 쓴다.
CSS를 수정한 뒤 레이아웃이 "이유 없이" 적용 안 되면, 먼저
`grep -n '\*/' assets/css/style.css`로 모든 주석 종료 지점을 나열해 각각이 실제로 의도한
`/*`와 짝을 이루는지 훑어본다 — 브라우저는 이런 파싱 실패를 콘솔 에러 없이 조용히 규칙을
버리는 방식으로 처리하므로 devtools 에러 로그로는 못 잡는다.
