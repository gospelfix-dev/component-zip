# 설계 결정 기록

세션 시작 시 `.claude/hooks/load-memory.sh` 가 이 파일을 컨텍스트로 주입한다.
코드만 봐서는 알 수 없는 **"왜"** 만 적는다. 코드 구조 설명은 쓰지 않는다.

## 이미지 캐러셀만 Swiper 로 바꾸고, 상품 갤러리는 스크롤 스냅으로 남긴 이유

처음엔 카드 안 이미지 캐러셀(`< >`)도 배열 인덱스를 직접 돌리는 바닐라 JS로 만들고
Swiper 를 아예 쓰지 않았다 — "화살표 버튼일 뿐 슬라이더가 아니다"라고 판단했었다.
이후 사용자가 "이미지 좌우로 움직이는 걸 Swiper 로 바꿔달라"고 명시적으로 요청해
`0002`/`0004` 와 같은 버전(8.4.7)을 `js/swiper.js`/`css/swiper.css` 로 벤더링했다.

**단, 상품이 여러 개일 때의 바깥 가로 스크롤(`.gallery__track`)은 그대로 CSS
`scroll-snap` 이다.** Swiper 는 카드 안쪽 이미지 전용이고, 카드 자체를 넘기는 용도가
아니다. 두 스크롤 영역이 둘 다 가로라 터치 제스처가 겹칠 수 있는데 — 이미지 위에서
스와이프하면 Swiper 가 먼저 가로채 이미지만 바뀌고, 이미지 바깥(제목·버튼 영역)에서
스와이프해야 상품 갤러리가 넘어간다. 카드가 1장뿐이면 체감되지 않는 트레이드오프다.

카드마다 별도의 `new Swiper()` 인스턴스를 만들고 `navigation.nextEl/prevEl` 에
**선택자 문자열이 아니라 해당 카드의 버튼 엘리먼트를 직접 넘긴다.** 모든 카드가 같은
클래스명(`.card__photo-prev` 등)을 쓰므로 문자열 선택자를 쓰면 첫 번째 카드의
버튼만 계속 잡힌다.

## 이미지 전환에 `effect: "slide"` 대신 `"cube"` 를 쓴 이유

사용자가 "좌우로 미끄러지는 느낌 말고 360도 회전하는 느낌"을 요청했다. Swiper 에는
진짜 "제품 360도 뷰어"(턴테이블로 찍은 24~36장을 드래그 각도에 매핑해 애니메이션 없이
프레임만 바꿔치기하는 방식) 전용 이펙트는 없다. 가장 가까운 내장 옵션이
`cubeEffect` 라 이걸 썼다 — 슬라이드가 입체 정육면체의 한 면처럼 회전한다.

**한계**: 상품 사진이 2~3장뿐이라(턴테이블 연속 프레임이 아니라 낱장 컷) 진짜 매끄러운
회전처럼 보이진 않는다. 또 `.card__slide` 배경이 투명이라(카드 배경이 그대로 비침)
정육면체 "박스"의 옆면 모서리가 보이지 않아 회전감이 `coverflow`/`slide` 대비 은은하다.
사진 장수를 늘리거나 진짜 프레임 매핑형 360 뷰어가 필요해지면 Swiper 이펙트로는
한계가 있다는 걸 감안한다.

## 상품 이미지를 저장소에 넣지 않은 이유

사용자가 "상품 이미지는 내가 넣을 것"이라고 명시했다. `data/products.json` 의
`images` 는 아직 존재하지 않는 파일 경로(`./imgs/light-hooded-tracksuit-1.jpg` 등)를
가리키며, `js/app.js` 의 `<img onerror>` 가 자리표시자 스타일로 대체한다.
이미지가 채워지기 전에도 레이아웃 검토가 가능해야 하기 때문이다.

## Iconly 아이콘을 그대로 쓰지 않고 자체 제작한 이유

Iconly 는 유료/라이선스가 있는 아이콘 세트다. 시안의 실루엣(뒤로가기 셰브론, 하트, 업로드,
비니 모자, 옷걸이, 큐브, 플러스)만 참고해 `stroke-width 1.5~1.8` 의 얇은 선 스타일로
자체 SVG 를 그렸다. 원본 아이콘 파일을 저장소에 포함하지 않는다.

## 사이즈 드롭다운을 `<select>` 대신 커스텀 리스트로 만든 이유

시안의 "Choose size" 버튼은 네이티브 `<select>` 로는 재현할 수 없는 알약 모양·그리드
드롭다운(`sizemenu`, 3열 그리드)이다. `role="listbox"` / `aria-expanded` / `aria-selected`
로 접근성을 최소한으로 갖췄지만, 완전한 네이티브 키보드 내비게이션(방향키 이동)은
아직 구현하지 않았다 — 필요해지면 `roving tabindex` 패턴을 추가한다.

## 장바구니에 실제 상태 저장소를 두지 않은 이유

이 컴포넌트는 시각적 상호작용을 보여주는 정적 데모다. 담긴 개수를 배지로 표시하거나
localStorage 에 남기는 기능은 요구되지 않았고, 추가하면 "장바구니 페이지"라는
범위 밖의 기능을 암묵적으로 약속하게 된다. 그래서 `card__add` 클릭은 토스트 안내 +
버튼 색 일시 변경(`data-added`)까지만 하고 상태를 유지하지 않는다.

## 미해결 / 검토 대기

- `imgs/` 가 비어 있다. 실사 상품 사진이 들어오면 `product-card-design-qa` 로
  `object-fit: contain` 크롭이 시안과 맞는지 다시 확인해야 한다.
- 카테고리 아이콘은 `beanie` `hanger` 2종만 정의했다. 다른 카테고리 상품을 추가하려면
  `index.html` 스프라이트에 심볼을 먼저 추가한다 (`.claude/rules/04-data-contract.md`).
